# UX/UI 设计方案｜安心 App

## 阶段 1：体验策略与信息架构

## 1. 文档目的

本阶段用于确定 `安心` 移动端 App 的体验方向、信息架构、导航结构、核心页面范围与基础视觉策略。

本阶段不展开高保真逐页细节，而是先解决以下问题：

- 用户第一次进入 App，是否能快速理解产品价值
- 高敏感主题下，界面是否足够温和、可信、不压迫
- 高风险功能是否在结构上先天可控
- MVP 页面是否足够少，但又能闭环完成配置

本阶段产出将直接作为：

- UI 原型设计输入
- 页面线框拆解依据
- 前端页面路由与模块拆分依据
- 设计系统初版输入

---

## 2. 产品设计定位

### 2.1 产品名称策略

- 主品牌名：`安心`
- 对外说明文案可使用：`安心托付，提前交代，事后有序`
- 在界面文案中尽量减少“死亡后”“身后”等直接表述，优先使用：
  - `意外预案`
  - `失联托付`
  - `授权执行`
  - `重要事项交代`

### 2.2 体验关键词

- 温和
- 可信
- 克制
- 清晰
- 有秩序
- 可撤回

### 2.3 避免的体验方向

- 殡葬感、沉重黑白风
- 保险推销感
- 纯工具后台感
- 过度科技化、冷冰冰的安全产品感

### 2.4 推荐视觉方向

采用 `静谧编辑感 + 医疗级可信感 + 家庭托付感` 的混合风格。

具体表现：

- 主色以柔和深青绿、暖灰白为主
- 高风险状态使用克制琥珀色与深红点缀
- 卡片圆角偏大，提升包裹感
- 页面留白偏宽，降低紧张感
- 插画或背景纹理以“纸张、晨雾、柔光、档案夹”意象为主

## 3. 设计原则

### 3.1 先解释，再操作

所有涉及授权、触发、文件释放、联系人通知的流程，都先解释“会发生什么”，再让用户配置。

### 3.2 先可逆，再不可逆

产品结构上优先暴露：

- 通知类动作
- 预警类动作
- 模拟演练

将不可逆动作隐藏在更深层，并明确风险说明。

### 3.3 一屏只做一件事

高敏感任务流程中，避免在同一屏同时要求用户：

- 理解规则
- 填写复杂表单
- 作出风险判断

### 3.4 先让用户获得安全感

首页与 onboarding 首先表达：

- 信息不会立刻对外公开
- 可随时暂停/修改
- 默认不会误触发正式执行

### 3.5 家属视角必须可理解

所有用户配置过的内容，最终都要能被联系人端以“下一步该做什么”理解，而不是一堆技术字段。

## 4. 目标用户体验拆解

### 4.1 本人视角

核心任务：

- 配置联系人
- 建立事务清单
- 上传重要文件
- 设置触发规则
- 做一次模拟演练

核心情绪：

- 一开始会犹豫
- 对误触发敏感
- 希望操作有掌控感

设计应对：

- 用清单式分步流程替代长表单
- 用“完成度”替代“复杂配置”
- 用“暂停保护”“模拟演练”增加安全感

### 4.2 联系人视角

核心任务：

- 确认身份
- 理解自己被赋予的角色
- 在事件触发后快速看到待办

核心情绪：

- 可能是突发进入
- 压力大
- 不清楚该做什么

设计应对：

- 页面必须少
- 信息必须按优先级排序
- 默认只显示“与你有关”的任务

## 5. 移动端信息架构

### 5.1 顶层结构

移动端 App 建议采用 `4 Tab + 1 个高优先级悬浮入口`。

底部 Tab：

1. `首页`
2. `托付清单`
3. `联系人`
4. `我的`

全局高优先级入口：

- `保险箱`

说明：

- `保险箱` 不放入底部 Tab，是因为它是高频认知入口但低频编辑入口，更适合作为首页卡片和全局快捷入口
- `触发规则` 不单独做 Tab，而挂在首页状态卡和“我的”中，避免用户误认为这是一个可随意开启的“自动执行开关”

### 5.2 一级页面定义

#### 首页
用于表达状态、安全感和下一步行动。

包含：

- 当前账户安全状态
- 配置完成度
- 下次存活确认时间
- 快捷入口
- 重要提醒

#### 托付清单
用于查看和管理预设事项。

包含：

- 事项分类
- 任务状态
- 风险级别
- 执行方式

#### 联系人
用于添加和管理信任联系人、执行人。

包含：

- 联系人列表
- 角色标签
- 通知顺序
- 授权范围摘要

#### 我的
用于处理账号、安全、套餐、帮助与法律文档。

包含：

- 账号安全
- 身份认证
- 存活确认设置
- 通知与提醒
- 协议与帮助

### 5.3 二级页面结构

#### 首页下

- 安全状态详情
- 触发规则设置
- 模拟演练
- 保险箱快捷面板

#### 托付清单下

- 清单列表页
- 新建事项页
- 事项详情页
- 模板选择页

#### 联系人下

- 联系人列表页
- 添加联系人页
- 联系人详情页
- 授权配置页

#### 保险箱下

- 文件列表页
- 上传页
- 文件权限页
- 文件释放规则页

#### 我的下

- 账号与实名认证
- 二次验证设置
- 通知设置
- 法律与隐私说明

## 7. 关键流程结构

### 7.1 首次使用主流程

`欢迎 -> 价值理解 -> 建立第一位联系人 -> 创建第一条托付事项 -> 上传第一份文件 -> 设置确认周期 -> 完成`

设计重点：

- 把第一次配置控制在 8 分钟内
- 允许跳过非关键字段
- 在第一个里程碑就显示“你的预案已开始生效”

### 7.2 日常低频维护流程

`首页查看状态 -> 更新联系人/事项 -> 完成一次存活确认 -> 查看下次提醒`

设计重点：

- 首页能快速解释当前是否安全
- 低频用户再次回来时能立即接上进度

### 7.3 高风险检查流程

`首页状态卡 -> 查看触发规则 -> 查看当前预警策略 -> 进入模拟演练`

设计重点：

- 强调可控
- 强调可暂停
- 强调不会单点误触发

## 8. 核心 UI 定义（阶段 1）

以下为本阶段需要确定方向的首批具体 UI。当前以结构与视觉意图为主，下一阶段再展开详细布局。

## 8.1 启动页 / 品牌欢迎页

### 页面目标

- 建立品牌第一印象
- 缓和用户对主题的紧张感
- 传达“这是一个值得托付的工具”

### 页面内容

- 品牌名：`安心`
- 副文案：`安心托付，提前交代，事后有序`
- 一个柔和但有记忆点的视觉主体
- 主按钮：`开始设置`
- 次按钮：`先了解怎么运作`

### 交互说明

- 首次进入显示完整欢迎页
- 二次进入可直接略过进入首页或登录

### 视觉建议

- 竖版移动端构图
- 中上区域为品牌与文案
- 中部为柔光插画或抽象档案意象
- 下部双按钮，按钮间层级分明

**提示词**: 移动端 app 欢迎页，品牌名“安心”，气质温和可信、非殡葬化、非保险推销感，柔和深青绿与暖灰白配色，晨雾感背景，纸张与档案夹意象，留白充足，中文界面设计，高级感，克制、专业、治愈、现代 app onboarding hero screen

## 8.2 Onboarding 价值介绍页

### 页面目标

- 解释产品能做什么
- 明确能力边界
- 建立“不误触发、不泄露、不乱执行”的信任

### 页面内容

- 3-4 张横向或纵向引导卡
- 每张卡只讲一个概念：
  - 提前托付联系人和事项
  - 意外或失联后自动通知
  - 文件按授权释放
  - 不会因单次失联直接误触发

### 交互说明

- 支持滑动浏览
- 页底有进度点
- 最后一页进入首次配置

### 视觉建议

- 插画不宜过拟人，可偏抽象信息图
- 每张卡保留大标题与一句解释

**提示词**: 移动端 app onboarding 多页引导界面，中文，主题为托付、联系人、文件保险箱、低误触发，编辑感排版，柔和深青绿、雾白、浅金点缀，抽象信息图与卡片结合，清晰图标，现代产品设计，高级但克制

## 8.3 首页 Dashboard

### 页面目标

- 让用户第一眼知道“当前状态是否正常”
- 明确下一步最该做什么
- 强化托付配置进度

### 页面内容

- 顶部状态卡：正常 / 待确认 / 已暂停
- 配置完成度卡
- 下次存活确认时间
- 快捷入口：
  - 添加联系人
  - 新建事项
  - 打开保险箱
  - 模拟演练
- 安心说明卡：`默认不会因一次未响应直接执行`

### 交互说明

- 状态卡可进入触发规则详情
- 配置完成度卡可跳到未完成模块

### 视觉建议

- 首页采用上轻下实布局
- 顶部状态卡具有明显层级
- 页面中段使用模块化卡片组合

**提示词**: 移动端 app 首页 dashboard，中文，安全托付主题，顶部大状态卡显示“当前正常”，下方配置完成度、存活确认时间、快捷操作卡片，柔和深青绿主色，奶白背景，大圆角卡片，专业可信，信息层级非常清晰，高端健康科技与家庭托付感结合

## 8.4 托付清单列表页

### 页面目标

- 帮助用户理解自己已经配置了哪些事项
- 快速发现未完成项和高风险项

### 页面内容

- 搜索
- 分类切换：账号 / 订阅 / 文件 / 线下事项
- 事项卡片：
  - 标题
  - 类型
  - 执行方式
  - 风险级别
  - 指定执行人

### 交互说明

- 顶部固定分类筛选
- 支持底部浮动按钮新建事项

### 视觉建议

- 列表比首页更偏信息密度
- 风险级别采用小标签，不喧宾夺主

**提示词**: 移动端 app 清单列表页，中文，事项管理界面，包含搜索、分类标签、任务卡片、风险等级胶囊标签、执行方式信息，清晰但不拥挤，深青绿与暖灰白为主，现代产品 UI，适度密度，可信赖的专业工具气质

## 8.5 联系人列表页

### 页面目标

- 让用户清楚当前已托付给谁
- 明确联系人角色差异

### 页面内容

- 联系人数量与完整度提示
- 联系人卡片：
  - 姓名
  - 关系
  - 角色标签
  - 通知顺序
  - 是否完成确认

### 交互说明

- 点击联系人进入授权详情
- 页面底部固定“新增联系人”

### 视觉建议

- 强化“关系感”而非“企业成员管理感”
- 用头像、关系标签和温和卡片建立亲近感

**提示词**: 移动端 app 联系人列表页，中文，家庭托付和信任联系人主题，头像卡片式布局，角色标签如“主联系人”“执行人”，温和可信，生活化但专业，青绿色和暖白色调，圆角卡片，现代移动端 UI

## 8.6 保险箱列表页

### 页面目标

- 让用户觉得文件被妥善保管
- 快速理解文件分级与释放规则

### 页面内容

- 文件分类标签
- 文件卡片：
  - 文件名
  - 文件类型
  - 查看权限
  - 释放条件
  - 最近更新时间

### 交互说明

- 支持上传按钮
- 支持筛选“仅自己可见 / 触发后释放 / 指定联系人可见”

### 视觉建议

- 比普通文件管理更强调安全与秩序
- 可使用轻微档案盒、锁具、封签图形元素

**提示词**: 移动端 app 文件保险箱页面，中文，数字保险箱与重要文件托管主题，档案管理感但温和高级，文件卡片、权限标签、释放条件标签，深青绿、米白、浅金点缀，圆角、安全感强、信息层次清楚

## 8.7 触发规则设置页

### 页面目标

- 让用户理解触发逻辑
- 降低对误触发的担忧

### 页面内容

- 当前确认周期
- 超时预警规则
- 联系人核实规则
- 冷静期说明
- 暂停保护入口

### 交互说明

- 每一项规则旁边都有简短解释
- 页面底部持续显示说明：`不会因单次失联直接进入正式执行`

### 视觉建议

- 这是全产品最需要“冷静和解释”的页面
- 采用步骤卡与说明块组合，而不是纯开关列表

**提示词**: 移动端 app 触发规则设置页，中文，高风险设置界面，重点展示确认周期、联系人核实、冷静期、暂停保护，视觉沉稳、清晰、可解释，深青绿配暖灰白，结构化说明卡，非极客设置页，强调安全和可控

## 8.8 模拟演练页

### 页面目标

- 增强用户掌控感
- 让用户在安全环境中理解未来流程

### 页面内容

- 演练说明
- 将发生的步骤时间线
- 不会真实通知的说明
- 开始演练按钮

### 交互说明

- 演练结果页展示：
  - 哪位联系人会收到什么
  - 哪个文件会在何条件下释放
  - 哪些动作不会自动发生

### 视觉建议

- 用时间线和阶段卡表达流程
- 气氛上应更像“预演”而不是“警报”

**提示词**: 移动端 app 模拟演练页面，中文，预演时间线设计，展示通知步骤、文件释放步骤、审核步骤，氛围理性、安心、可控，柔和深青绿与米白色，时间线卡片设计，现代移动端 UI，专业且友好

## 10. 设计系统初步建议

### 10.1 色彩

- 主色：深青绿
- 背景：暖灰白
- 辅助：雾灰、浅金
- 成功：柔和绿色
- 预警：琥珀色
- 高风险：深砖红

### 10.2 字体与排版

- 中文建议偏现代人文黑体
- 标题字重明显高于正文
- 页面标题尽量短句化
- 表单说明文字保持高可读而不过于技术化

### 10.3 组件倾向

- 大圆角卡片
- 清晰的 section 标题
- 标签式风险分级
- 说明块与步骤块并存
- 高风险按钮不默认主按钮样式

### 10.4 动效建议

- 首页卡片轻微上浮出现
- onboarding 采用柔和横向转场
- 风险设置页避免夸张动画
- 模拟演练页时间线可渐进展开

## 12. 本阶段结论

`安心` 的移动端 App 不应被设计成一个沉重的“临终工具”，而应被设计成一个温和、可信、可控的“重要事项预案助手”。

阶段 1 的核心结论是：

- 结构上以 `首页 / 托付清单 / 联系人 / 我的` 为主骨架
- 体验上优先建立安全感、解释力与掌控感
- 视觉上采用温和可信而非冷峻庄重的方向
- MVP 的 UI 重点不是“自动执行有多强”，而是“用户敢不敢先配置”
