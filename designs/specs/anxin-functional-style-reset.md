# 安心 App 功能块与界面风格重启稿

## 状态

- 目的：放弃上一轮布局形式，先重新确定各页面功能块与界面风格。
- 当前阶段：设计前置确认，不生成预览图，不进入实现。
- 依据：`README.md`、`TODO.md`、`docs/spec/project-requirements.md`、`docs/spec/design-requirements.md`、`docs/spec/technical-solution.md`、当前 `src/app` 与 `src/pages` 路由事实。
- 保留：上一轮认可的浅色、清新、淡雅方向。
- 放弃：上一轮“浅雾工作台”的具体布局形式，包括状态票据、工作台、分类台账、底部表单板、阶段卡组等固定结构。

## 当前设计边界

### 当前实现事实

当前 App 是单机 MVP，底部 Tab 仍是：

- `home`
- `items`
- `my`

当前独立页面包括：

- `welcome`
- `report`
- `items/new`
- `items/[id]`
- `helpers`
- `helpers/new`
- `helpers/[id]`
- `my/trigger-state`

### 目标心智

目标产品化方向是逐步走向：

- `首页`
- `预案`
- `执行`
- `我的`

但该方向不能直接当作当前路由事实。当前设计应在不大改路由的前提下，先让用户形成“预案”的心智：事项、协助人、确认周期、触发演练都是同一份安心预案的不同组成。

## 产品体验原则

1. 一屏只承担一个主要任务。
2. 所有敏感动作先解释会发生什么，再让用户操作。
3. 优先暴露可逆动作：确认、补充、暂停、演练、查看、本地备份。
4. 不让单次失联看起来会触发正式执行。
5. 不把 App 表现成遗嘱、公证、账号接管或保险销售工具。
6. 家属或协助人视角必须能看懂下一步做什么。
7. 状态必须同时使用文字与视觉标识，不只靠颜色。

## 页面功能块

### 1. Welcome

页面目标：

- 建立“安心托付”的第一印象。
- 降低高敏感主题的压力。
- 明确告诉用户：信息不会立刻公开，可暂停，可修改，不会误触发。

必须功能块：

- 品牌与一句话定位：`安心托付，提前交代，事后有序`。
- 三条边界承诺：
  - 不会因一次失联直接执行。
  - 不会立刻公开信息。
  - 可以随时暂停或修改。
- 首次设置将发生什么：
  - 写入欢迎完成状态。
  - 写入一次与 `report` 等价的正式申报记录。
  - 进入首页。
- 主按钮：`开始设置`。

可选功能块：

- 简短预案组成预览：事项、协助人、确认周期。
- 隐私与本地 MVP 说明，保持弱展示。

不应出现：

- 长篇产品教育。
- 强烈恐惧文案。
- 大面积法律、保险、殡葬联想视觉。

### 2. Report / 每日申报状态

页面目标：

- 每天首次进入 App 时，让用户完成一次低压力状态确认。
- 告诉用户今天的确认会被记录，但不会触发公开或执行。

必须功能块：

- 今日日期与申报状态。
- 当前状态说明：今天是否已申报。
- 最近申报时间。
- 托付保护边界：规则未触发 / 已暂停 / 仅本地记录。
- 主按钮：`确认今日状态` 或当前文案体系中的等价动作。
- 规则摘要：连续失联、多阶段提醒、人工复核，不能单次触发。

可选功能块：

- 查看确认规则。
- 暂停今日提醒。
- 最近 3 次确认记录的轻量摘要。

不应出现：

- 像风险警报一样的强红色首屏。
- 把确认误导成法律状态或安全评分。
- 一屏放入复杂触发规则配置。

### 3. Home

页面目标：

- 第一眼说明当前安心预案是否正常。
- 给出一个最值得现在完成的下一步行动。
- 让用户理解预案准备程度，但不把它包装成保证或评分。

必须功能块：

- 当前状态摘要。
- 今日申报状态或下次确认提示。
- Readiness summary：
  - active 事项数量。
  - active 协助人数量。
  - 事项与协助人覆盖情况。
  - 触发演练状态。
- 下一步行动，只突出一个。
- 边界文案：可暂停、可修改、不会因单次未响应直接执行。

可选功能块：

- 快速入口：新增事项、添加协助人、查看触发演练。
- 本地备份提醒，但不抢主任务。

不应出现：

- 多个同级大卡片同时争抢注意力。
- 法律有效性、安全评分、完成率保证。
- 过度仪表盘化的数据展示。

### 4. Items / 预案事项

页面目标：

- 管理本地 active 事项。
- 让用户把“事项”理解为安心预案的一部分，而不是普通待办列表。

必须功能块：

- 页面标题与圆形 `+` 新建入口。
- active 事项列表。
- 空状态说明与创建入口。
- 事项摘要：
  - 标题。
  - 类型。
  - 简短说明。
  - 关联协助人或待关联提示。
  - 当前状态：草稿、待补充、已准备、已归档等。
- 编辑与归档入口。

可选功能块：

- 按类型筛选：文件线索、账号线索、家庭事项、医疗事项、财务线索。
- 待补充提醒。
- 与协助人的覆盖关系提示。

不应出现：

- 多选批量操作。
- 像任务管理 App 的效率优先视觉。
- 暗示平台能直接接管账号或转移资产。

### 5. New Item / Item Detail

页面目标：

- 低压力地创建或编辑一条重要事项。
- 帮用户写清楚“未来别人第一步该做什么”。

必须功能块：

- 事项名称。
- 事项类型。
- 简短说明。
- 给协助人的处理指引。
- 关联协助人。
- 状态：草稿 / 已准备 / 待补充。
- 保存动作。

可选功能块：

- 文件或位置线索。
- 风险等级或敏感程度，但不能制造恐惧。
- 示例文案。

不应出现：

- 一次要求填写过多敏感字段。
- 无可见 label 的输入框。
- 默认要求上传文件或输入密码。

### 6. Helpers / Contacts

页面目标：

- 管理本地可信协助人。
- 让用户清楚“托付给谁”和“对方未来看到什么”。

必须功能块：

- active 协助人列表。
- 新增协助人入口。
- 协助人信息：
  - 姓名。
  - 关系。
  - 联系方式。
  - 角色或授权摘要。
  - 已关联事项数量。
- 编辑与归档入口。
- 本地 MVP 边界：不会自动通知、不读取通讯录、不赋予法律身份。

可选功能块：

- 未来可通知渠道占位。
- 示例说明：协助人会收到怎样的指引。

不应出现：

- 企业成员管理感。
- 通讯录授权暗示。
- 法律执行人身份暗示。

### 7. Trigger State

页面目标：

- 解释确认周期、漏确认阈值、暂停保护和演练逻辑。
- 降低误触发担忧。

必须功能块：

- 当前触发策略状态：正常 / 已暂停 / 演练中。
- 确认周期与漏确认阈值。
- 多阶段触发说明：
  - L1 预警。
  - L2 联系人核实。
  - L3 人工复核。
  - L4 授权执行。
- 暂停 / 恢复保护。
- 本地模拟演练入口。
- 明确说明：演练不发送真实消息，不产生外部执行。

可选功能块：

- 最近演练结果。
- 冷静期、冻结、申诉路径说明。
- 风险说明详情。

不应出现：

- 纯开关列表。
- 类似报警面板的强刺激设计。
- 暗示单一信号进入正式执行。

### 8. My / Settings

页面目标：

- 管理语言、皮肤、触发设置、协助人入口和本地备份。
- 承载低频但重要的 App 设置。

必须功能块：

- 语言设置。
- 皮肤运行时状态，但不暴露下载器、manifest、hash 等内部实现。
- 备份导出。
- 备份导入预览与替换说明入口。
- 触发设置入口。
- 协助人入口。
- 帮助、隐私、法律边界说明。

可选功能块：

- 当前 App / skin 版本。
- QA 或预览态标识，仅开发环境显示。

不应出现：

- 高风险操作与普通设置混放在第一层。
- 技术内部字段直接给用户。
- 备份导入不说明替换语义。

## 界面风格方向

### 风格名称

清透封存层片。

### 风格定义

整体保留浅色、清新、淡雅，但不再追求“卡片工作台”。新的视觉语言应来自项目设计需求里的“平面封存层片 + 封签时间线”：

- 预案像被整理进一组轻薄、清透、可打开的封存层片。
- 封签表达状态，而不是装饰。
- 时间线用于表示确认、预警、复核、执行的边界。
- 页面结构应更像“预案册”的不同章节，而不是普通 SaaS 卡片。

### 色彩方向

沿用浅色认可方向，并向现有设计需求靠拢：

| 角色 | 建议色值 | 用途 |
| --- | --- | --- |
| 雾感背景 | `#F3F8F7` | 页面底色 |
| 浅色层片 | `#FFFEFA` | 主内容面 |
| 弱化面板 | `#E7EFEC` | 次级区域 |
| 主行动 | `#0A6B63` | 主按钮、可信状态 |
| 深可信文字 | `#174842` | 强调标题 |
| 正文墨色 | `#1B2D3A` | 主要文字 |
| 辅助文字 | `#607078` | 说明文字 |
| 封签/复核 | `#B7791F` | 预警、冷静期、复核 |
| 安全确认 | `#2F8A67` | 确认态 |
| 高风险 | `#8A2D2A` | 不可逆风险，谨慎使用 |
| 边框 | `#C9DAD5` | 层片边界 |

### 形态语言

- 层片：浅色、轻边框、低阴影，像叠放但不厚重。
- 封签：短标签、状态戳、日期签，表达状态与确认边界。
- 章节：不同页面像预案册的不同章节，但不做纸张纹理。
- 时间线：只用于真实顺序或触发阶段，不做装饰编号。
- 留白：首屏要轻，敏感信息不堆满。

### 排版

- 使用系统 CJK sans 作为主体。
- 标题 28-32pt，克制、明确。
- 正文 15-16pt，保持可读。
- 状态戳、日期、审计标记可使用等宽感或紧凑标签。
- 不使用大段 serif，不做复古纸本风。

### 图标与插图

- 图标使用线性、圆角、统一 stroke 的矢量图标。
- 不用 emoji 作为结构图标。
- 插图如需要，只使用抽象层片、封签、文件夹、路径，不用真实遗嘱、蜡封、皮革、厚书。

### 动效方向

- 只服务于“层片展开、封签确认、状态推进”。
- 微动效 150-300ms。
- 支持 reduced motion 等价路径。
- 不使用装饰性漂浮、复杂视差或大面积动效。

## 下一轮设计图建议

下一轮如果进入设计图生成，建议先做两张图：

1. 全页面信息架构总览：展示每个页面的功能块位置和层级，不追求高保真装饰。
2. 关键页面高保真：优先做 `report` 和 `home`，确认每日申报与首页状态心智。

确认后再扩展到：
