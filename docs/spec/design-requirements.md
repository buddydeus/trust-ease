# 项目设计需求

## 设计定位

`安心` 不应被设计成沉重的临终工具，也不应像保险销售页、后台管理系统或冷硬
安全产品。它应是一个温和、可信、可控的“重要事项预案助手”。

设计目标：

- 让用户第一次进入 App 时快速理解产品价值。
- 在高敏感主题下保持温和、不压迫。
- 让高风险功能在信息结构上天然可控。
- 让 MVP 页面尽量少，但足以完成本地配置闭环。
- 让用户理解：信息不会立刻公开，可随时暂停或修改，不会因一次未响应直接执行。

## 品牌与文案策略

- 主品牌名：`安心`
- 对外说明：`安心托付，提前交代，事后有序`
- 优先词汇：`安心`、`托付`、`意外预案`、`失联托付`、`授权执行`、
  `重要事项交代`、`预案`、`协助人`、`确认周期`、`暂停保护`、`模拟演练`、
  `执行记录`
- 谨慎使用或减少直接出现：`死亡后`、`身后` 等高压词。

文案语气：

- 冷静、具体、不煽情、不销售。
- 风险状态必须说明原因、边界和恢复路径。
- 空状态必须给出下一步行动。
- 不使用技术内部词直接面向用户，例如 trigger-service、connector、runtime。

## 体验关键词

- 温和
- 可信
- 克制
- 清晰
- 有秩序
- 可撤回

## 必须避免的体验方向

- 殡葬感、沉重黑白风。
- 保险推销感。
- 纯工具后台感。
- 过度科技化、冷冰冰的安全产品感。
- 暗示自动接管第三方账号。
- 暗示单次失联会直接正式执行。
- 暗示 App 已具备法律、公证、继承或强制执行能力。

## 交互原则

### 先解释，再操作

涉及授权、触发、文件释放、联系人通知、备份导入等流程时，必须先解释会发生
什么，再提供操作。

### 先可逆，再不可逆

优先暴露：

- 通知类动作。
- 预警类动作。
- 模拟演练。
- 暂停保护。
- 本地查看和本地备份。

不可逆或高风险动作应更深、更明确，并需要解释、确认和审核。

### 一屏只做一件事

高敏感任务流程中，避免同屏同时要求用户理解规则、填写复杂表单和作出风险
判断。

### 家属和协助人视角必须可理解

联系人或协助人最终看到的内容应回答“下一步该做什么”，而不是展示原始技术
字段。

### 状态不只靠颜色

任何状态必须同时使用文字、图标或明确标签，不能仅靠颜色表达。

## 信息架构方向

当前实现事实：

- 当前底部 Tab 是 `首页 / 事项 / 我的`。
- 已有独立路由包括 `welcome`、`report`、`trigger-state`、`items/new`、
  `items/[id]`、`helpers`、`helpers/new` 等。

目标产品化方向：

- `首页`：状态安抚和下一步行动。
- `预案`：创建和管理完整预案单元，预案拥有事项、文件、协助人、触发规则和动作。
- `执行`：演练或触发后的执行状态、时间线、回执、审核记录和空安全态。
- `我的`：身份、安全、语言、皮肤、确认设置、帮助、法律与隐私。

迁移原则：

- `预案` 是目标主心智，不是简单把 `items` 改名。
- 从当前实现迁移到 `首页 / 预案 / 执行 / 我的` 需要单独规格、路由改造、i18n、
  截图脚本和测试。
- 目标 IA 不应削弱当前单机 MVP 的本地、可解释、低风险边界。

## 核心页面需求

### Welcome

目标：

- 建立品牌第一印象。
- 缓和用户对主题的紧张感。
- 传达这是一个值得托付、可控、不会误触发的工具。

当前行为：

- 首次安装第一次打开进入 `welcome`。
- 点击 `开始设置` 写入欢迎完成状态。
- 同时写入与 `report` 页面等价的正式申报记录。
- 完成后跳转 `home`。
- 后续启动不再进入 `welcome`。

视觉：

- 使用当前 skin 语义色，不使用偏暖黄旧纸感。
- 使用整理好的托付册、层叠卡片或平面封存层片意象。
- 底部只保留清晰主按钮。

### Home

目标：

- 第一眼说明当前状态是否正常。
- 明确下一步最该做什么。
- 强化托付配置进度和可控感。

应包含：

- 当前状态卡。
- 下次确认或申报状态。
- readiness summary。
- 事项、协助人、触发演练等本地下一步行动。
- 明确边界文案，例如不会因单次未响应直接执行。

### Items / 预案事项

当前 MVP 需求：

- 显示本地 active 事项。
- 空状态温和说明，并提供创建入口。
- 支持创建、编辑、归档。
- 事项卡片展示标题、类型、摘要、风险或执行方式相关信息。
- 顶部使用圆形 `+` 按钮新建事项。
- 不恢复多选操作。

目标产品化方向：

- 后续从单独事项列表演进为 `预案` 视角。
- 预案详情中聚合事项、文件、协助人、触发规则和执行动作。

### Helpers / Contacts

目标：

- 让用户清楚当前托付给谁。
- 体现关系感，而不是企业成员管理感。
- 显示姓名、关系、联系方式、角色或授权摘要。
- 明确本地 MVP 不会自动通知、不读取通讯录、不赋予法律身份。

### Trigger State

目标：

- 让用户理解确认周期、漏确认阈值、暂停保护和演练逻辑。
- 降低对误触发的担忧。

要求：

- 使用步骤卡和说明块，不做纯开关列表。
- 页面底部或关键位置持续说明不会因单次失联直接正式执行。
- 演练必须被标注为本地预览，不发送真实消息。
- 高风险状态更像“预演”和“复核”，不是“警报”。

### My / Settings

目标：

- 管理语言、皮肤、触发设置、协助人入口和本地备份。
- 展示皮肤运行时状态，但不暴露下载器内部实现细节。
- 备份导入导出必须说明本地文件、用户管理、导入替换当前本地预案。

### Execution

目标设计方向：

- 展示安全空态、演练时间线或真实触发后的执行状态。
- 以时间线说明确认提醒、协助人回执、人工审核、文件释放等步骤。
- 当前单机 MVP 不应暗示已有真实通知、审核后台或外部执行能力。

## 视觉系统

设计记忆点：

- `平面封存层片 + 封签时间线`
- 预案被表现为平面 dossier / envelope / folder 层片。
- 封签带不只是装饰，而是表达 draft、ready、watching、review、execution 等状态。

颜色方向：

- `#F3F8F7`：雾感背景。
- `#FFFEFA`：浅色卡片。
- `#E7EFEC`：弱化面板。
- `#0A6B63`：主行动和可信状态。
- `#174842`：深可信文字。
- `#1B2D3A`：正文墨色。
- `#607078`：辅助文字。
- `#B7791F`：封签、复核、冷静期、预警。
- `#2F8A67`：安全确认。
- `#8A2D2A`：不可逆或正式执行风险，谨慎使用。
- `#C9DAD5`：边框。

形态：

- App 背景安静。
- 卡片边界清楚，圆角可偏大。
- 扁平层片和封签可作为主视觉。
- 只使用克制阴影，不做强拟物。

避免：

- 真实纸张纹理、蜡封、绳结、皮革、厚重书本。
- 深色殡葬风。
- 紫蓝渐变模板感。
- 随机数字装饰。
- 图标或状态只靠 emoji。

## 字体与排版

- UI 正文优先使用高可读 CJK sans，例如 `Noto Sans SC`、`PingFang SC`、
  `Source Han Sans SC` 或系统 sans。
- 品牌或封签瞬间可少量使用克制 serif，例如 `Noto Serif SC`。
- 日期、确认次数、辅助码、审计标记可使用等宽字体。

字号方向：

- 屏幕标题：28-32pt。
- 区块标题：20-22pt。
- 卡片标题：17-18pt。
- 正文：15-16pt。
- 辅助文字：13-14pt。
- 工具标签：11-12pt，只用于代码、状态戳或辅助码。

## 无障碍与可用性

- 主要触控目标至少 44pt。
- icon-only 控件必须有可访问标签。
- 表单必须有可见 label、helper text 和邻近错误信息。
- 高风险动作与主流程分离，并需要解释页。
- 动效克制，支持 reduced-motion 等价路径。
- 安全区适配顶部标题、底部 Tab 和底部 CTA。
- 文案必须在中文、繁中、英文中都能放入卡片和按钮，不溢出、不重叠。

## 文案与国际化要求

- 所有长期用户可见文案通过 i18n 读取。
- 同步维护 `zh-CN`、`zh-TW`、`en-US`。
- 风险、备份、触发、导入、确认等文案必须显式说明边界。
- 不允许只更新一种语言。

## 设计交付验证

视觉或页面变更后应按范围验证：

- 文案变更：`pnpm check:local` 或相关 i18n 测试。
- 页面行为变更：对应 Jest 测试。
- 皮肤相关变更：`pnpm test tests/skin --runInBand`。
- 真实运行截图：`pnpm check:qa:runtime` 或 `pnpm thumbs`。
- 单机 MVP 进入 QA 前：`pnpm check:qa`。
