# 项目需求

## 项目定位

`Trust Ease` 是 `安心` 移动端产品的原型项目。产品目标是帮助用户在高风险
事件发生前，提前整理重要事项、可信联系人、授权说明、文件线索、触发规则和
执行路径。

产品本质不是密码托管工具，也不是第三方账号接管工具，而是：

- 授权编排平台：记录用户授权、联系人、事项、文件、证据材料和处理指令。
- 触发判断系统：用多阶段、多信号和人工复核降低误触发风险。
- 执行路由层：把事项分流到自动通知、官方流程引导、人工协助等路径。

## 产品目标

- 让用户提前完成重要事项预案，而不是在事件发生后让家属临时寻找信息。
- 降低亲友理解信息、整理材料、联系平台和推进事务的成本。
- 把可逆、低风险动作优先暴露，把不可逆动作放到更深、更明确的审核流程中。
- 在合规前提下降低误触发概率，避免单次失联或一次漏确认直接进入执行。
- 在单机 MVP 阶段先验证用户是否愿意配置、是否能理解产品边界和触发安全性。

## 非目标与边界

产品和文案必须持续保留以下边界：

- 不替代遗嘱、公证、律师意见或法定继承流程。
- 不以直接保管第三方平台明文密码作为核心方案。
- 不承诺接管全部第三方账号。
- 不承诺转移全部资产。
- 不直接办理需要法定身份、法院文书、公证文书或线下核验才能完成的事项。
- 不用“推测死亡”或单一信号触发不可逆删除、释放或执行。
- 不绕过第三方平台风控、验证码、2FA 或平台条款。

## 目标用户

- 有线上账号、云盘、订阅、域名、内容资产、跨境账号等数字资产或线索的用户。
- 独居、高频出行、海外出差、户外活动或跨时区生活用户。
- 希望给伴侣、父母、子女或朋友留下清晰处理指引的家庭责任用户。
- 面临重病、慢病、失能风险或高龄场景的用户。

次级用户包括可信联系人、协助人、执行人、律师、公证员、保险顾问、本地线下
服务商和未来的平台审核员。

## 核心角色

- `Owner`：本人，配置联系人、事项、文件、触发规则，并可暂停或修改预案。
- `TrustedContact`：可信联系人，接收提醒，参与近况核实。
- `Executor`：执行人，只查看被授权事项并推进对应任务。
- `Partner`：合作方，只处理被派发工单所需的最小信息。
- `Reviewer`：审核员，处理证据审核、风险复核、冻结、申诉和异常流程。

## 核心能力

长期目标能力包括：

- 账户、身份认证和安全设置。
- 可信联系人和授权范围管理。
- 重要事项清单，包括线上账号线索、订阅、文件、线下事项、财务或保险线索。
- 文件保险箱和分级释放规则。
- 触发规则、存活确认、预警、联系人核实和模拟演练。
- 通知编排，包括模板、渠道、回执和重试。
- 执行路由，包括 API 自动化、官方流程引导和人工协助。
- 风险审核、冻结、申诉和误触发控制。
- 审计日志、敏感访问记录和合规留痕。
- 移动端国际化和受控皮肤体验。

## 当前单机 MVP 范围

当前实现聚焦单设备、本地闭环，不依赖后端、账号、云同步、短信、邮件、推送
或真实远程协助流程。

已落地或当前重点包括：

- 首次启动进入 `welcome`。
- 点击 `开始设置` 写入 `hasSeenWelcome = true`，并写入与 `report` 页面等价
  的正式申报记录。
- 完成后进入 `home`，后续启动不重复进入欢迎页。
- 本地事项创建、编辑、归档。
- 本地可信协助人创建、编辑、归档。
- 事项与协助人关联。
- 本地触发策略查看、暂停、恢复和模拟演练。
- 首页 readiness summary，作为本地、建议性的准备状态，不是法律或安全评分。
- 本地备份导出与导入，导入前必须预览并明确替换语义。
- `my` 页面展示语言、皮肤运行时状态、备份入口和触发设置入口。
- 三语文案：`zh-CN`、`zh-TW`、`en-US`。

## 核心流程

### 首次配置

```text
welcome -> value explanation -> first contact -> first trust item
  -> first document -> confirmation cycle -> active plan
```

当前单机 MVP 先实现了首次欢迎页、正式申报、本地事项、本地协助人、触发演练
和 readiness summary，后续可继续补齐完整 first plan wizard。

### 日常维护

```text
home status -> update contacts/items -> report safe -> next reminder
```

首页必须告诉用户当前是否正常、下一步应做什么，并持续强调可暂停、可修改、
不会因单次未响应直接执行。

### 高风险检查

```text
status card -> trigger rules -> pre-alert strategy -> simulation
```

用户应能看到触发逻辑是可解释、可暂停、可演练的。

### 触发执行

```text
normal -> missed-check -> pre-alert -> contact-verification
  -> pending-review -> approved-execution -> executing -> completed
```

高风险状态必须支持 `paused`、`frozen`、`appealed` 等退出或阻断路径。

## 触发策略要求

推荐策略是分层触发、多信号评分和人工复核：

- L1 预警：连续未确认、多渠道未响应或联系人主动反馈，仅提醒本人，不释放文件。
- L2 关注：超时、联系人核实异常、设备或 App 活跃中断组合出现，通知主联系人核实。
- L3 待审核：多轮联系失败、多名联系人确认异常、可信材料出现，进入人工审核。
- L4 正式执行：审核通过、用户曾明确授权、风险等级允许后才执行对应任务。

必须避免：

- 单一信号直达正式执行。
- 长期失联直接等同不可逆执行。
- 缺少冷静期、冻结、申诉或人工复核的敏感释放。

## 交付与后续路线

当前路线：

1. 完成并稳定单机 App MVP。
2. 用 `pnpm check:qa` 和 `pnpm check:qa:runtime` 进入 QA。
3. 在 macOS / iOS 真机上验证。
4. 将 QA 问题记录到 `.bugs/*.md` 并修复。
5. 稳定后再考虑 monorepo 物理拆分、后端、账号、同步、通知和远程协作。
