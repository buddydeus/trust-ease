# 信笺秩序

## 1. 方案定义

`信笺秩序` 是 `安心 App` 的品牌型 UI 方向。

它的核心不是“安全后台”，而是“被认真整理好的私人托付册”。

视觉重心：

- 暖纸感背景
- 页签、封签、归档式层次
- 温和但郑重的情绪
- 高留白与编辑式标题

本方案必须保持独立，不与 `静默实用` 的标准工具型组件语言混用。

---

## 2. 体验关键词

- 温和托付
- 家书感
- 安静归档
- 低压迫
- 有记忆点
- 郑重但不沉重

避免：

- 殡葬感
- 保险推销感
- 科技安防后台感
- 过度文艺化
- 夸张拟物

---

## 3. 视觉系统

### 3.0 Expo UI 组件约束

本方案中的组件风格统一以 `Expo UI` 为实现基准。

依据 Expo 官方文档，`@expo/ui` 是一组直接映射到 SwiftUI 与 Jetpack Compose 的原生 UI 组件，因此本方案的控件外观不能脱离原生语义另起一套。

设计约束：

- 主按钮、次按钮使用原生按钮比例与按压反馈，不做厚重拟物封边。
- 分段切换、表单输入、开关、弹出式选择等控件，优先贴近 Expo UI 对应的系统组件外观。
- 卡片可以保留品牌气质，但交互控件本体必须像原生控件，而不是品牌插画的一部分。
- 不设计仅能靠自定义绘制实现的复杂控件结构。
- 允许通过配色、留白、容器层次表达 `信笺秩序`，但不改变原生控件的基本识别方式。

落地映射建议：

- 按钮：Expo UI `Button` 风格
- 输入：Expo UI `TextInput` 风格
- 选择与菜单：Expo UI `Picker` / `ContextMenu` 风格
- 开关：Expo UI `Switch` 风格

这一约束优先级高于品牌装饰语言。

### 3.1 色板

- 主色：`#6EA8B6`
- 深文字：`#33515A`
- 纸白背景：`#FAF8F3`
- 次背景：`#EEF6F8`
- 分隔线：`#DDE7E9`
- 强调色：`#E5D3A8`
- 风险提示：`#B48179`
- 成功确认：`#88B7BE`

使用原则：

- 大面积背景不用纯白，统一走暖纸底。
- 主色改为更轻的海盐蓝绿，用来减轻压抑感，同时保留托付册的清透感。
- 强调色只用于页签、重点角标、进度提示，不大面积铺开。
- `失联` 与 `死亡` 都用低刺激标签，不做强警报红。

### 3.2 字体与排版

- Hero 标题：32-36，`semibold`
- 页面标题：26-28，`semibold`
- 卡片标题：18-20，`medium`
- 正文：15-16，`regular`
- 注释：12-13，`regular`

排版原则：

- 标题有明显存在感，允许更大的上下留白。
- 正文必须易读，不使用强装饰字体。
- 不使用真实手写体做主字体；如需强调，只允许极少量点缀。

### 3.3 材质与容器

- 卡片像压平的纸页，而不是玻璃或金属板。
- 边框比阴影重要，阴影只承担轻层次。
- 允许轻微“页签露出”和“层叠错位”，但必须克制。
- 容器边角圆润，像被妥善收纳的纸件。

### 3.4 圆角与间距

- 主卡圆角：28
- 普通卡片圆角：22-24
- 按钮圆角：18-20
- 标签圆角：999

- 页面左右边距：20-24
- 大区块间距：24-32
- 卡片内边距：18-24

布局节奏偏松，不追求信息塞满。

### 3.5 按钮系统

- 主按钮：海盐蓝绿实底，白字，像封签
- 次按钮：纸白底，灰绿描边
- 文字按钮：更像脚注入口
- 风险按钮：浅棕灰底，二次确认后再执行

补充约束：

- 按钮轮廓、内边距、按压反馈遵循 Expo UI 的原生按钮风格。
- “像封签”只体现在颜色和层次上，不体现在夸张造型上。

### 3.6 标签系统

- `失联`：浅雾蓝底，深灰蓝字
- `死亡`：温粉棕底，深棕灰字
- `默认规则`：柔金底，深灰蓝字

标签应像纸签，不像运营后台状态 pill。

首页事项卡特殊规则：

- 不显示 `死亡 / 失联` 文字。
- 仅在卡片右上角使用低刺激颜色丝带角标区分触发条件。
- `失联` 使用浅雾蓝丝带，`死亡` 使用温粉棕丝带。
- 丝带采用柔和下垂的缎带挂签形式，不用硬折角。
- 丝带只承担状态区分，不承担文案说明，避免首页压迫感。

### 3.7 图标与动效

- 图标使用柔和线性风格
- 不使用硬朗科技图标
- 页面进入：淡入 + 上浮 12-16px
- 卡片出现：像纸页铺开
- 时长：180-240ms

禁止：

- 弹跳
- 过度缩放
- 高对比闪烁反馈

交互动效补充：

- 控件级反馈以 Expo UI 的原生按压、聚焦、切换节奏为准。
- 品牌动效只作用于页面层和容器层，不改变原生控件的反馈逻辑。

---

## 4. 文案口吻

语言像被认真写下的托付说明，克制、完整、温和。

推荐表达：

- `先把重要的事，安静地交代好`
- `今天也为自己留下一次平安记录`
- `先写下第一件需要被托付的事`
- `这件事已经写好`
- `默认死亡 = 3 次未申报，之后仍可调整`

避免：

- `立即执行`
- `触发引擎`
- `高危操作`
- `系统自动判定`

## 5. 页面高保真定义

## 5.1 欢迎页

### 页面目标

- 建立第一印象
- 让用户感受到“值得托付”
- 不在第一屏制造死亡压迫感

### 布局

- 顶部：品牌区
- 中部：纸页层叠主视觉
- 底部：双 CTA

### 内容结构

- 品牌名：`安心`
- 副标题：`提前交代，事后有序`
- 主文案：`先把重要的事，安静地交代好`
- 副文案：`意外、失联或无法亲自处理时，你写下的事项会按约定被看见。`
- 主按钮：`开始设置`
- 次按钮：`先了解怎么运作`

### 视觉说明

- 主视觉由 3-4 层纸页与页签构成。
- 纸页上只露出少量字样，如 `联系人`、`事项`、`确认记录`。
- 背景从暖纸白向雾白渐变，边缘有极轻的晨雾纹理。

## 5.2 申报页

### 页面目标

- 让“我今天还在”成为全产品最明确的日常动作
- 在情绪上给人一种郑重但不紧张的确认感

### 布局

- 顶部：日期与短引导
- 中部：单张确认函卡片
- 下部：辅助入口

### 内容结构

- 顶部文案：`今天也为自己报个平安`
- 首次校验说明：`今天首次进入，需要完成一次完整确认`
- 主按钮：`我今天还在`
- 脚注入口：`查看完整校验方式`

### 视觉说明

- 主按钮像盖章位，四周留白很大。
- 首次完整校验用一张窄说明纸签承载，不用系统警示条。
- 快捷申报模式下只保留轻确认反馈，不再在底部重复展示最近一次申报。

## 5.3 首页

### 页面目标

- 先传达“你现在是安全的”
- 让 `存活天数` 成为情绪锚点
- 再直接进入事项查看与整理

### 布局

- 顶部：扉页式主卡
- 中段：事项列表
- 下段：新增与继续整理入口

### 内容结构

- 主卡标题：`从注册那天起`
- 主数字：`第 127 天`
- 陪伴文案：`今天也继续好好生活。`
- 列表分组：`线下事项`、`线上事项`
- 事项卡片：标题、摘要、无文字缎带角标
- 主 CTA：`新增事项`
- 次入口：`先了解怎么运作`

### 视觉说明

- 主卡像翻开的扉页，是整套方案的视觉中心。
- 不使用仪表盘、统计图、科技线条。
- 首页中段直接就是事项分组列表，不再单独拆出事项列表页。
- 线下与线上事项用页签式分组标题区分，但不再强调“事项总览”或“当前触发状态”。
- 事项卡的触发条件通过右上角颜色丝带表达，不再出现 `死亡 / 失联` 文字标签。

## 5.4 创建事项页

### 页面目标

- 让用户感觉在“填写托付页”，而不是在配置复杂系统
- 减少首次创建的心理负担

### 布局

- 顶部：翻页式类型标签
- 中段：分块表单
- 底部：固定保存操作区

### 类型切换

- `线下事项`
- `线上事项`

当前项像翻到前面的标签页，未选项退后半层。

### 线下事项结构

1. 协助人
2. 处理说明
3. 事项标题
4. 触发条件
5. 联系方式与附件

### 线上事项结构

1. 脚本代码
2. 执行目标说明
3. 审核说明
4. 触发条件

### 首次创建提示

- 文案：`默认死亡 = 3 次未申报，可稍后调整`
- 形式：夹在表单中的说明签，不打断主流程

### 底部按钮

- `保存线下事项`
- `保存线上事项`

---

## 6. 状态设计

### 空状态

- 强调“从第一件事开始”
- 留白多于说明块

### 已完成状态

- 使用 `这件事已经写好`
- 不用强成功绿勾

### 风险提示状态

- 使用说明签或注记块
- 先解释影响，再给动作

### 申报成功状态

- 像收到一张平安回执
- 文案可用：`今天的平安记录已完成`

### 保存成功状态

- 文案可用：`这一页已归档`

---

## 7. 交付原则

- 首页、欢迎页、申报页必须保持品牌性。
- 首页承担事项列表能力后，仍不能丢掉纸页与归档感。
- 所有风险表达都要低刺激。
- 不能出现黑白重压、冷蓝科技风、强警报红。

---

## 8. 一句话总结

`信笺秩序` 要让用户感觉：这些重要的事，已经被安静、认真、妥帖地收好了。
