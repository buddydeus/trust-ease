# 静默实用

## 1. 方案定义

`静默实用` 是 `安心 App` 的工具型 UI 方向。

它的核心不是“私人托付册”，而是“安静、成熟、可信的日常管理工具”。

视觉重心：

- 干净背景
- 标准化模块
- 清晰状态层级
- 低情绪波动
- 高复用效率

本方案必须保持独立，不使用 `信笺秩序` 的纸页、信件、封签等隐喻。

---

## 2. 体验关键词

- 安静
- 直接
- 稳定
- 清楚
- 低情绪化
- 成熟产品感

避免：

- 家书感隐喻
- 文艺化排版
- 明显材质感
- 过度品牌装饰
- 通用模板感过强

---

## 3. 视觉系统

### 3.0 Expo UI 组件约束

本方案中的组件风格统一以 `Expo UI` 为实现基准。

依据 Expo 官方文档，`@expo/ui` 直接映射 SwiftUI 与 Jetpack Compose 的原生组件，因此本方案要尽量使用原生控件语义和样式边界，而不是额外发明一套视觉语言。

设计约束：

- 按钮、输入框、选择器、开关、底部操作区等组件都按 Expo UI 的原生风格来设计。
- 组件优先呈现“系统控件感”，而不是品牌装饰感。
- 列表卡片和页面容器可以体现 `静默实用` 的秩序感，但卡片内控件必须保持原生识别度。
- 不使用依赖复杂自绘的装饰型控件。
- 组件尺寸、圆角、间距、交互反馈以原生平台逻辑优先。

落地映射建议：

- 按钮：Expo UI `Button`
- 输入：Expo UI `TextInput`
- 日期/时间：Expo UI `DateTimePicker`
- 菜单/选择：Expo UI `Picker` / `ContextMenu`
- 开关：Expo UI `Switch`

这一约束高于纯视觉风格统一。

### 3.1 色板

- 主色：`#74B7C4`
- 深文字：`#2E4D56`
- 主背景：`#F6FBFC`
- 次背景：`#EAF5F8`
- 分隔线：`#D8E6EA`
- 辅助灰蓝绿：`#A9C3C9`
- 风险提示：`#B07F78`
- 成功确认：`#8ABDC6`

使用原则：

- 以纯净背景和分区层级为主，不依赖纹理与材质。
- 主色改为更轻的海盐蓝绿，用于核心操作和状态焦点，降低整体压感。
- 风险色仅用于提醒，不作为视觉主角。

### 3.2 字体与排版

- Hero 标题：30-32，`semibold`
- 页面标题：24-26，`semibold`
- 卡片标题：17-18，`medium`
- 正文：14-15，`regular`
- 注释：12-13，`regular`

排版原则：

- 完全 UI 化。
- 依靠字号、字重、间距建立层级。
- 不做编辑式标题拉扯。

### 3.3 容器与边界

- 卡片结构统一，尽量保持高度和内边距一致。
- 阴影极弱，以边框和背景层次做区分。
- 组件语言优先复用效率，不强调主题材质。

### 3.4 圆角与间距

- 主卡圆角：24
- 普通卡片圆角：18-20
- 按钮圆角：16-18
- 标签圆角：999

- 页面左右边距：20
- 大区块间距：20-24
- 卡片内边距：16-20

节奏紧凑但不拥挤。

### 3.5 按钮系统

- 主按钮：海盐蓝绿实底
- 次按钮：浅底或描边
- 文字按钮：标准产品文字入口
- 风险按钮：标准风险色系统

补充约束：

- 按钮形态、按压反馈、禁用态遵循 Expo UI 的原生按钮风格。
- 不为了品牌感额外增加不必要的描边、立体感或装饰分层。

### 3.6 标签系统

- `失联`：浅雾蓝底，深灰蓝字
- `死亡`：浅粉棕底，深棕灰字
- `默认规则`：浅暖灰底，深文字

标签像成熟产品状态系统，不做纸签风格。

首页事项卡特殊规则：

- 不显示 `死亡 / 失联` 文字。
- 改用卡片右上角的低刺激颜色丝带角标区分状态。
- `失联` 使用浅雾蓝丝带，`死亡` 使用浅粉棕丝带。
- 丝带采用柔和下垂的缎带挂签形式，不用硬折角。
- 角标只做状态提示，不抢标题与摘要信息。

### 3.7 图标与动效

- 图标：标准线性或轻填充图标
- 动效：淡入、颜色变化、状态切换
- 时长：140-200ms

禁止：

- 主题化转场
- 夸张仪式感动画
- 无意义装饰动效

交互动效补充：

- 控件级反馈遵循 Expo UI 的原生切换与按压节奏。
- 页面层可以有轻微过渡，但不能盖过原生控件的系统反馈。

---

## 4. 文案口吻

语言应像成熟产品，短、准、稳定。

推荐表达：

- `管理重要事项与触发保护`
- `今天首次进入，需要进行完整确认`
- `默认不会因一次未响应直接执行`
- `还没有事项`
- `事项已保存`

避免：

- 过度陪伴式表达
- 隐喻型句子
- 冗长引言

---

## 5. 页面高保真定义

## 5.1 欢迎页

### 页面目标

- 快速解释产品价值
- 用清晰结构建立信任
- 让用户知道接下来会配置什么

### 布局

- 顶部：品牌与一句价值说明
- 中部：3 张能力卡
- 底部：双 CTA

### 内容结构

- 品牌名：`安心`
- 主标题：`管理重要事项与触发保护`
- 副文案：`提前配置联系人、事项和触发条件，在需要时按规则处理。`
- 能力卡：
  - `每日确认`
  - `事项托付`
  - `低误触发保护`
- 主按钮：`开始设置`
- 次按钮：`先了解怎么运作`

### 视觉说明

- 无纸张、信件、封签隐喻。
- 依靠功能卡和留白建立专业感。
- 图标风格统一，避免品牌插画化。

## 5.2 申报页

### 页面目标

- 清晰完成当天的申报动作
- 让用户一眼知道当前是完整确认还是快捷申报

### 布局

- 顶部：标题与说明
- 中部：主按钮
- 下部：辅助入口与必要说明

### 内容结构

- 标题：`今日申报`
- 首次说明：`今天首次进入，需要进行完整确认`
- 主按钮：`我今天还在`
- 状态块：
  - 今日确认方式
- 辅助入口：`查看完整校验方式`

### 视觉说明

- CTA 是全页唯一强焦点。
- 说明与状态放入标准信息卡。
- 页面要像“完成一个明确任务”，而不是仪式页。
- 不在底部重复展示最近一次申报。

## 5.3 首页

### 页面目标

- 先告诉用户当前状态正常
- 再直接给出事项列表与整理入口

### 布局

- 顶部：状态主卡
- 中段：事项分组列表
- 下段：新增入口

### 内容结构

- 状态：`当前正常`
- 数字：`第 127 天`
- 辅助：`今天已完成申报`
- 分组：
  - `线下事项`
  - `线上事项`
- 每条事项卡片包含：
  - 标题
  - 简要说明
  - 无文字缎带角标
- 操作：
  - `新增事项`
  - `先了解怎么运作`

### 视觉说明

- 首页像成熟工具首页，不像品牌海报。
- 首页直接承载事项列表，不再单独拆出事项列表页。
- 模块高度统一，优先可读性和复用性。
- 事项卡的触发条件通过右上角颜色丝带表达，不再出现 `死亡 / 失联` 文字标签。

## 5.4 创建事项页

### 页面目标

- 让用户快速进入录入
- 提升表单可读性和确定性

### 布局

- 顶部：标准 segmented control
- 中段：标准 section 表单
- 底部：固定保存栏

### 类型切换

- `线下事项`
- `线上事项`

当前类型用标准选中态，不做翻页隐喻。

### 线下事项结构

1. 协助人
2. 处理说明
3. 事项标题
4. 触发条件
5. 联系方式与附件

### 线上事项结构

1. 脚本代码
2. 执行目标说明
3. 审核说明
4. 触发条件

### 首次创建提示

- 文案：`死亡 = 3 次未申报，创建后可修改`
- 形式：顶部标准提示条

### 底部按钮

- `保存线下事项`
- `保存线上事项`

---

## 6. 状态设计

### 空状态

- 使用标准空态组件：图标 + 标题 + 说明 + CTA

### 已完成状态

- 用标准成功反馈
- 示例：`事项已保存`

### 风险提示状态

- 使用标准提示卡
- 先说明规则，再给操作

### 申报成功状态

- 文案：`今日申报已完成`

### 保存成功状态

- 文案：`事项已保存`

---

## 7. 交付原则

- 所有页面保持统一模块化语言。
- 功能优先于情绪氛围。
- 不引入纸张、信封、页签、归档册等具象叙事。
- 欢迎页、首页、表单页都应像同一套成熟产品界面。
- 首页承担列表能力后，仍要保持模块化与清晰度。

---

## 8. 一句话总结

`静默实用` 要让用户感觉：这是一个可靠、安静、规则清楚、可以长期使用的重要事项管理工具。
